# 代码风格、注释与文档规则

1. 项目内的 `AGENTS.md`、格式化配置和既有代码风格优先；不要格式化或整理与当前任务无关的代码。
2. 注释使用中文；领域术语、标识符和代码片段保留英文。
3. 新增或修改模块、关键类型和关键状态时，应补充与其复杂度相称的注释，可以详细说明局部且非显然的所有权、生命周期、线程、锁、顺序和失败语义。不要要求每个普通字段都写重复性注释。
4. 关键函数和关键分支应解释设计意图、调用契约和选择当前实现的原因，不复述显而易见的代码行为，也不在代码注释中复制模块级或跨模块设计。
5. 可执行约束优先通过类型、断言和测试表达；文档、模块 README 和代码注释的内容分工遵循 `design-documentation.md`，只更新直接承载相应内容的位置。
6. Rust 的 `use` 按标准库、第三方 crate、工作区内其他 crate、当前 crate 分组，组间留空行；项目已有约定优先。
7. Rust 和 C/C++ 的多行注释使用连续的 `///`，不使用连续的 `//`。
8. Rust 和 C/C++ 字段带有多行注释时，与前一个字段之间保留一个空行。
9. 不要新增零散的自由函数：先查找并复用已有工具函数；确需新增时，将同一职责的状态和行为组织到合适的 `struct` 中。
10. 组合优先于继承
