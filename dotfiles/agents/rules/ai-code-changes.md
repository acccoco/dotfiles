# 对 AI 修改代码的约束

请将代码改动加工成便于人工 Review 的形式：

给出设计方案、修改代码和编写 Review Packet 时，应区分设计理念、设计不变量和当前实现细节。主动说明方案保持或改变了哪些重要不变量，以及相应证据和风险，但不要求使用固定的不变量登记格式。

1. 每个提交只能包含一个可验证的行为变化。
2. 行为修改不能与格式化、重命名、文件移动混合。
3. 每个提交必须可独立编译和回滚。
4. 不以 300 行作为唯一拆分标准；优先按语义和风险拆分。
5. 每个提交提供 Review Packet：
   - 本提交的行为命题
   - 修改前后的行为差异
   - 非目标
   - 推荐阅读入口
   - 关键调用链
   - 必须保持的不变量
   - 最可能出错的三个位置
   - 风险与测试的对应关系
   - 相对原计划的偏差
6. 不要逐行复述 diff。
7. 机械性代码应单独提交并明确标注。
8. 无法证明的结论必须标明是推断，不得宣称已经验证。
